## Qué se hizo

Módulo `waitlist` y migración `0016_waitlist` (`WaitlistEntry` `@pii`, una entrada viva por cliente y paquete). `POST /booking-requests` con país fuera de `salesCountries` crea entrada (solo nº de viajeros; sin instantánea, cupos ni canje) y responde `outcome: 'waitlisted'`. País validado contra los 249 códigos ISO (`ZZ` es el centinela de borrado). `GET /admin/waitlist` (`waitlist.entry.read`, no es alcance de clave; cursor `(packageId, position)`). Web: confirmación «no es solicitud ni reserva».

## Cómo se comprobó

- Entra en lista, sin importes/cupos/canje → `non_resident_joins_waitlist`, `country_decides_outcome` (`apps/api/test/modules/waitlist/waitlist.test.ts`); `country_not_served_waitlists` sustituye a `country_not_served_409` (`bookings/request.test.ts`).
- Clave de idempotencia única entre reservas y lista aun sin registro de plataforma, contacto comparado; país auditado → bloque «one Idempotency-Key»; ISO → `country_must_be_an_assigned_iso_code`; paginación → `paging loses nothing`; SQL → `waitlist_database_guards`; privacidad → `waitlist_privacy`.
- Web → `waitlist_page_says_waiting_list_not_booking`, `waitlist_answer_recognised`. Local en base limpia: lint, tipos, API (1229, sin `backup.test.ts`) y web (502); CI verde.
