# 3.4 Método manual: transferencia con PayID, referencia única y confirmación en el panel

- **Estado:** hecha con pendientes
- **PR:** #71
- **Modelo:** Sonnet
- **Revisor:** pendiente (lo lanza el coordinador; ruta de pagos)
## Qué se hizo
La API da instrucciones de pago (beneficiario, PayID o BSB, importe y referencia) sin pasarela; el personal registra con step-up el dinero llegado como pago `inbound` y puede anularlo con motivo (revierte reparto y reapertura del depósito). El ID de extracto bancario (no la referencia de la reserva) identifica cada transferencia. Migración 0032, ajustes por método, web de pago y panel "Bank transfers".
## Cómo se comprobó
- Referencia única, confirmación idempotente (repetida y concurrente), otra cantidad o reserva con la misma referencia → 409; importe de la API, sin recargo, nunca por pasarela ni base: `apps/api/test/modules/payments/manual.test.ts`.
- Fallos (sin cuenta, hook que falla, versión vieja, sin step-up ni permiso, estado no pagable, anular dos veces o una reserva confirmada): mismo archivo.
- Dos transferencias iguales con ID distinto se registran; el mismo ID repite (replay); referencia de reserva o `MT-XXXXXX` → 422; estados no pagables: mismo archivo.
- Transiciones: `unit.test.ts` y `webhooks.test.ts`. Web: `apps/web/src/app/checkout-pages.test.tsx`.
