# 0.fix-2 Check demo data inside the compose smoke job

- **Estado:** hecha con pendientes
- **PR:** #17
- **Modelo:** Sonnet
- **Revisor:** no aplica

## Qué se hizo
`scripts/check-compose-demo-data.mjs` (sin dependencias) y un paso nuevo en el job `compose-smoke`, tras `docker compose up --wait`: lee `docker compose logs api`, entra como propietario demo por `http://localhost:3000/api` (contraseña, TOTP calculado en el script y cabeceras Origin y X-MT-CSRF) y comprueba que `/admin/tables/Task/rows` da 6 filas. Sin código de producto.

## Cómo se comprobó
- Credenciales demo en el log, entrada por el proxy y 6 filas `Task` → `scripts/check-compose-demo-data.test.mjs` (9 pruebas con servidor simulado y vectores RFC 6238; se ejecutan en `pnpm lint`) y el paso de CI «Demo data is present».
- El job falla si falta el seed: sin bloque «Demo owner» en el log, con contraseña o código erróneos o con un número de filas distinto de 6, el script sale con código 1 (pruebas «missing…», «wrong…»).
- YAML válido (actionlint).

## Sin verificar
Docker no existe en el hilo: el paso contra el compose real solo se ve en CI (resultado en el PR). El script no imprime las credenciales.

## Decisiones tomadas sin Oscar
El criterio «solo en development» se cumple sin tocar el seed (decisión 15 del plan de 0.3): compose usa `APP_ENV=development`, así que el bloque debe aparecer; en `test` y `ci` el seed no imprime nada (`seed-cli.test.ts`, «prints credentials only in development»). Se deshace borrando el paso y el script.

Nada. Dependencias añadidas: ninguna.
