## Qué se hizo

`docker/Dockerfile` recibe `ARG WEB_ORIGIN` antes de `next build` (y lo deja como `ENV` en la etapa web). `deploy/docker-compose.prod.yml` lo pasa como `build.args` a web y api (una sola capa de build) y como `environment` de web, siempre con `${WEB_ORIGIN:?...}`. Documentado en `deploy/production.env.example` y `docs/deploy/guide.md`.
`scripts/check-deploy-config.mjs` falla si falta en el build de web, en el entorno de web o en el de api, o si se fija a localhost / `http://`.

## Cómo se comprobó

- Compose de producción correcto → `node scripts/check-deploy-config.mjs` (ok).
- Falta el build arg, falta en web, falta en api, localhost y http → `scripts/check-deploy-config.test.mjs` (test nuevo "task 1.fix-1"; 17 pruebas de scripts pasan).
- `pnpm lint` y `pnpm typecheck` en verde en local.
