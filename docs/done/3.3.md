# 3.3 Libro de pagos, reembolsos de la pasarela y adaptador de Stripe (experimental)
- **Estado:** hecha con pendientes (Stripe sin sandbox real: `experimental`)
- **PR:** #72 · **Modelo:** Opus · **Revisor:** plan: cambios (§12, aplicados); código: pendiente
## Qué se hizo
Migración `0033_ledger_refunds`: libro append-only, cuadrado por moneda al confirmar, sin asientos añadidos después (`createdTxId`), y `refunds` solo `external` hasta 4.5. `LedgerService` asienta cobros, reembolsos, reversiones y reasignaciones del plan, con una clave por hecho. Reembolsos hechos en el panel de la pasarela, por webhook y barrido de 24 h; revisión que para recordatorios y cobros. Adaptador `stripe` contra un Stripe falso; comprobación diaria del libro; `payments:stripe-test-account`.
## Cómo se comprobó
- Sin datos de tarjeta → Checkout alojado; `create_input_has_no_card_fields`, `adapter_sources_have_no_card_fields` (las dos baterías: simulador y Stripe local, 31 cláusulas cada una).
- Webhook duplicado o fuera de orden → `stripe_webhook_duplicate_out_of_order_bad_signature`, `same_success_via_two_event_types_posts_once`, `invalid_then_valid_same_event_id_processed_once` (`stripe-flow.test.ts`); reembolsos en `refunds.test.ts`.
- Misma clave, un cobro → `same_idempotency_key_charges_once` (una sola transacción en el libro), `create_retry_uses_row_createdAt`, `late_create_retry_looks_up_then_refuses` (`stripe.unit.test.ts`).
- Asientos inmodificables por la API → `ledger_entries_cannot_be_updated_or_deleted`, `entries_cannot_be_added_to_committed_transaction`, `only_ledger_service_writes_ledger` (`ledger.test.ts`, `ledger.unit.test.ts`).
- Libro = cobrado − reembolsado → la primera prueba de `ledger_postings_table` y los escenarios de `refunds.test.ts`, con `check()` limpio; `ledger_split_property` (2.000 secuencias); `ledger_check_flags_injected_difference`.
- Pasarelas apagadas → sin cambios (pruebas de 3.1 y 3.5). Claves en variables de entorno → `no_stripe_keys_in_repository`, `stripe_test_account_refuses_live_keys_and_reads_env_only`.
- Transferencias de 3.4 → `inbound_payment_posts_once`, `mistaken_inbound_voided_reverses_ledger_and_allocation` (`manual.test.ts`; el libro sigue los ganchos de 3.4).
- P11 y hallazgo 2 → `mode, booking and currency consistency`, `non_production_refund_on_live_account_rejected`, `webhook_metadata_id_from_other_account_not_matched` (Stripe y reembolsos). Local: base propia, API completa (salvo `backup.test.ts`), lint y tipos.
