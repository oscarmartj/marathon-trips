## Qué se hizo
Plan `docs/plans/6.5-waitlist-promotion.md`, migración `0021_waitlist_offers`. Un residente que pide un paquete `waitlist`/`sold_out` entra en la lista con su petición. Al liberarse plazas (rechazo, cancelación, caducidad) el motor de estados ofrece, en la misma transacción, a la primera entrada a la que le caben; la oferta retiene las plazas, manda correo y caduca a las 48 h. Aceptar crea una solicitud normal con el precio del motor; rechazar o salir pasa la plaza al siguiente. Web: botón, `/waitlist/[id]` y `/admin/waitlist`.
## Cómo se comprobó
- Cancelación promociona al primero → `cancellation_promotes_first_waitlisted`; el que no cabe conserva su sitio → `promotion_skips_entry_that_does_not_fit_and_keeps_its_place` (`apps/api/test/modules/waitlist/offers.test.ts`, igual para las demás).
- Plaza retenida frente a solicitud pública → `waitlist_offer_holds_released_slot_against_public_request`. Rechazo, caducidad, salida, borrado de cliente → `decline_expire_and_withdraw_promote_next`, `erasing a customer…`.
- Aceptar: `accept_creates_request_moves_stock_once`, `accept_twice_same_booking`, `accept_after_expiry_409`, `accept races with the periodic expiry`. Concurrencia: `concurrent_cancellations_offer_each_entry_once`, `cancel_vs_public_request`.
- Correo `offer_email_sent_while_open_and_never_after_it_ended`; opción borrada `changed_catalogue_expires_entry_and_continues`; `non_resident_never_offered`; SQL `waitlist_offer_database_guards`; rutas ajenas 404 con tres fixtures en `every_owned_route_rejects_other_customer`.
- Web `apps/web/src/app/waitlist-offer-pages.test.tsx`; e2e `apps/web/e2e/waitlist.spec.ts` (slot 15), pasada en local con Chrome. Local: lint, API completa salvo `backup.test.ts` (1836) y web (566).
