## Decisiones tomadas sin Oscar
Implementación propia en vez de Better Auth (plan §3.1). Límite por IP propio en memoria, sin `@nestjs/throttler`. El proxy de la web no reenvía la IP del cliente salvo con `WEB_TRUSTED_PROXY_HOPS` (8.7): hasta entonces el límite por IP es por ruta para todo el sitio. Cada intento cuenta antes de comprobarse; un acierto que no crea sesión lo devuelve. El acceso de clientes va tras el flag `auth.customer_sign_in` (apagado si falta; el seed lo enciende en desarrollo). Evento `auth.user.logged_in` (el formato de 0.4 no admite mayúsculas). Solo `privacy_purge_expired`; `privacy_erase_customer` es de 5.5. Todo se deshace con una migración o un cambio de flag.

## Bloqueado por algo externo
**Obligatorio antes de cualquier despliegue (8.7):** fijar `TRUST_PROXY` y `WEB_TRUSTED_PROXY_HOPS` al alojamiento real; hoy el límite por IP de las rutas de entrada cuenta todo el sitio junto (la API solo ve la web). En compose la API ya no publica el puerto 4000. Volúmenes de Docker anteriores: ejecutar `scripts/db-init.sh` o `docker compose down -v` (permiso `mt_privacy` → `mt_owner`).
