# 3.5 Checkout en la web con aceptación de condiciones (parcial: dinero aparcado, solo simulador)
- **Estado:** hecha con pendientes (sin revisión Opus todavía: la lanza el coordinador)
- **PR:** #44
- **Modelo:** Sonnet · **Revisor:** pendiente (plan propio en `docs/plans/3.5-checkout-simulator.md`)
## Qué se hizo
Migración `0023_terms_acceptance` (tabla inmutable con instantánea del texto, versión, huella y fecha). API: `GET checkout-terms`, `POST terms-acceptance` y `POST payments/refresh`; iniciar un pago exige haber aceptado el texto vigente; la dirección de retorno lleva `?ref=`. Web: `/checkout/[reference]`, `/payments/return`, enlace «Continue to payment» en la solicitud aprobada.
## Cómo se comprobó
- Métodos activos por país → los da la API (`methods` del plan, manifiestos y país de residencia); `checkout-pages.test.tsx` `shows_the_apis_amounts_untouched_and_only_the_methods_it_sends`; e2e (solo tarjeta del simulador; sin «Pay later»).
- Condiciones con versión y fecha → `checkout.test.ts` (API, 20 casos: instantánea con cliente, doble aceptación, versión/huella viejas, 422, edición posterior, sin página, 404/401, inmutabilidad como rol de la API y como propietario); e2e (aceptación con `acceptedAt` y versión).
- Pagar sin aceptar no guarda nada → `paying_without_acceptance_is_409_and_stores_nothing`; e2e (aviso y sin intento vivo).
- La web no calcula ni envía importes → `checkout.test.ts` web (`start_body_is_only_a_method`, `a_changed_amount_from_the_api_is_shown_as_sent`); el importe sale del plan; redirección solo https o localhost (`redirect_refuses …`).
- Sin datos de tarjeta → la web no tiene campos de tarjeta ni importe (unitaria y e2e); se paga en la página alojada del simulador.
- Nada se da por cobrado por la dirección → `refresh_after_the_hosted_page_paid_but_the_webhook_is_unprocessed`, `outcomeOf`; e2e: pago, rechazo y visitante sin sesión.
- Todas las pasarelas apagadas → `with_every_gateway_off_the_plan_says_so_and_terms_still_work`; la página muestra «no_payment_method_available» sin error.
- Accesibilidad básica → fieldset/legend, radios y casilla con etiqueta, región de términos enfocable, un solo h1, aviso `role=alert`; localizadores por rol en el e2e (que encontró y corrigió dos regiones con el mismo nombre).
- Revisión Opus del PR: corregidas las 7 observaciones (cliente en la aceptación, repetición con la misma clave, 503 neutro y sin reintento con tarea abierta, await, http solo desde localhost, intento vivo). Local en base propia `mt_t35`: lint, tipos, API completa (1.903 pruebas; fallan solo `backup.test.ts` y la importación CSV de catálogo, igual que en `main`), 609 pruebas de web, `checkout.spec.ts` en Chrome (dos pasadas).
