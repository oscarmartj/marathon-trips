## 1. What exists and what is missing

Exists: the booking state machine (the only writer of `bookings.status`), whose `cancel` event today reaches `cancelled` only from `requested` and `approved` and answers 409 `cancellation_needs_payments` from `deposit_paid`, `confirmed` and `balance_paid` (`MONEY_CELLS`); the payments `cancel` hook (`PaymentScheduleService.onCancel`), which refuses any booking with money collected and otherwise supersedes every active item; release of claims and promo code once, then waitlist promotion in the same transaction (6.5); immutable snapshots, amendments with a money port (6.3); the derived allocation and `ledger.reallocate`, which moves money between `customer_funds` and `customer_overpayments` from the active items; app refunds (4.5) whose amount is `refundable(p)` = the payment's overpayment share, computed under the booking's lock, with purposes `overpayment_return` (allowed), `price_reduction` and `cancellation` (409); the DB check `refunds_purpose_scope_check` (overpayment only); the deferred trigger `mt_payment_plan_matches_booking`, which wants active items = 0 in `cancelled`/`refunded`; `todayInBrisbane(dbNow)`; the one rounding helper `applyBps` (`pricing/engine/rounding.ts`).

Missing: policies and tiers; which policy a booking was sold under; the `Cancellation` record; the penalty calculation; the penalty plan; cancellation refunds and their cap; customer self-cancellation; panel and customer pages.

## 2. Decisions taken without Oscar (conservative, reversible)

1. **Where things live.** `CancellationPolicy`, `CancellationTier` and the package assignment in `pricing` (plan 0.1, 5.3); the pure calculation in `pricing/engine/cancellation.ts` (the engine is the only place an amount is derived); `Cancellation` and `CancellationService` in `bookings` (6.3 precedent: no `changes` module, bookings owns every row a cancellation writes); payments joins through a money port like `AmendmentMoneyPort`. Events: the existing `bookings.booking.cancelled` plus `bookings.cancellation.recorded` (instead of plan 0.1's `changes.cancellation.completed`). Undo: move the service if a `changes` module ever exists.
2. **The policy is frozen at submission.** New nullable column `booking_snapshots.cancellationPolicyId`. The request (2.4) and quote acceptance (2.5) write the package's assigned policy at that moment; an amendment (6.3) copies it from the base snapshot and never re-reads the package (a DB trigger enforces equality with the previous version). An active policy is immutable (trigger), so "the policy of the snapshot" is the terms the customer bought. Changing a package's policy never alters existing bookings. Quotes: frozen at acceptance, not at quote time (the acceptance page shows the policy). Undo: a migration that also stores it on quotes.
3. **Which penalty applies by state.**

   | State at cancellation | Penalty basis | Penalty |
   |---|---|---|
   | `requested`, `approved` (deposit not covered: no contract yet) | `not_contracted` | 0; everything collected becomes refundable |
   | `deposit_paid`, `confirmed`, `balance_paid` with a policy on the current snapshot | `policy` | from the tier (section 4) |
   | the same states without a policy (sold before 6.4 or from a package without one) | `no_policy` | 0, **staff only**; the customer gets 409 `customer_cancellation_rejected_until_policies_exist` (finding 5). Without agreed terms nothing can be kept |
   | `completed`, `declined`, `expired`, `cancelled`, `refunded` | — | 409 `transition_not_allowed`, as today |

   Every cancellation from any allowed state writes one `Cancellation` row (penalty 0 included), so P8's "owed in `cancelled` = `Cancellation.penaltyMinor`" has one source. Pre-6.4 cancelled bookings have none (owed 0, as P8 says).
4. **Days before departure.** `days = departureDate − today`, calendar dates, `today = todayInBrisbane(dbNow(tx))`, `departureDate` = `Booking.departureDate` of the current snapshot (extra nights before included: the day the customer's trip starts). Signed: negative after departure. A tier applies when `days ≥ tier.minDaysBeforeDeparture`; tiers are read from the highest threshold down; the tier with threshold 0 is mandatory and also covers every negative day (`cancellation_after_departure_uses_final_tier`). So a policy has no gaps by construction.
5. **Penalty larger than what was collected (finding 7).** The policy penalty is stored in full (`policyPenaltyMinor`), but the booking only ever owes `penaltyMinor = min(policyPenaltyMinor, max(collected, 0))`; the rest is `waivedMinor`, recorded and shown, **never collected after cancelling** (a cancelled booking already refuses payment attempts, links and reminders). Test `penalty_above_collected_is_not_charged`. Alternative for Oscar: keep chasing the difference (a new plan item and the payment flow for `cancelled`): not built.
6. **Refunds are not sent automatically.** Cancelling computes `refundableMinor` and opens a task for Oscar ("Refund due on MT-…"); staff send each refund from the existing 4.5 panel with purpose `cancellation` (amount from the server, section 6). Alternative: an after-commit job that requests them; not built (money leaves only by a person's click, as in 4.5).
7. **Customer self-cancellation is off by default.** Setting `customerCancellationsEnabled` (financial, default `false`, like 6.3's `customerAmendmentsEnabled`). Customers can cancel only `deposit_paid`, `confirmed` or `balance_paid` bookings with a policy, not after the departure date (`days < 0` → 409 `customer_cannot_cancel_after_departure`), and must send the digest of the quote they saw. `requested`/`approved` bookings: the customer asks Oscar (as today).
8. **Cancellation is refused while money is moving**, with the booking locked: a live attempt in `pending` (a debit sent to the bank) → 409 `cancellation_blocked_by_pending_payment`; an app refund `requested`/`pending` → `cancellation_blocked_by_refund_in_progress`; an external refund `pending` or a `late_pending_at_gateway` refund → same code; a dispute `open`/`evidence_submitted` → `cancellation_blocked_by_dispute`. Attempts in `created`/`requires_action` do not block: they are cancelled at the gateway by the existing after-commit job; if one succeeds late, its money is an overpayment (existing `late_success_on_cancelled_booking_recorded_with_task`). Undo: relax one guard.
9. **No penalty override, no partial cancellation.** Waiving or lowering a penalty is a courtesy refund (follow-up task named in 4.5); cancelling one traveller of several is an amendment (6.3). Both out of scope.
10. **Policy rules.** `percent` (0–10 000 bps of `baseTotalMinor`), `fixed_per_person` (minor units × places), `fixed_per_booking`; every penalty capped at `baseTotalMinor` (finding 4: penalties start from the snapshot and never exceed it). Fixed tiers carry a currency; a policy's fixed tiers share one currency, stored on the policy (`currency`, null when all tiers are percent); it can be assigned only to packages in that currency. No monotonicity rule between tiers (Oscar's business), the panel shows the table as entered.
11. **Ledger.** The penalty stays in `customer_funds` (allocated to the penalty item); recognising it as revenue, and its GST, belong to 4.6/6.6 and Oscar's accountant (`FINAL-REVIEW`). Nothing posts revenue here.
12. **Places for `fixed_per_person`:** every traveller slot in the current snapshot's configuration, runners and supporters alike.

## 3. The rounding rule (stated once)

Plan 0.1, 1.1, as implemented by `applyBps`: integer arithmetic, to the minor unit, **half up on the absolute value**. `percent`: `penalty = applyBps(baseTotalMinor, penaltyBps)`; `fixed_per_person`: `penaltyMinor × places`; `fixed_per_booking`: `penaltyMinor`; then `min(…, baseTotalMinor)`. Nothing else divides: `engine/cancellation.ts` calls `applyBps` and the existing AST test (only `rounding.ts` divides) keeps covering it. Tested by `penalty_rounding_half_up` (amounts ending in exactly .5 minor units, odd totals × 3 333 bps, 1 bps, 10 000 bps).

## 4. The calculation (pure, `pricing/engine/cancellation.ts`)

```
quoteCancellation({ policy | null, basis, state, departureDate, today, baseTotalMinor, places, currency, collectedMinor })
  → { basis, daysBeforeDeparture, tier | null, policyPenaltyMinor, penaltyMinor, waivedMinor, refundableMinor }
```

- `basis` from section 2.3; `not_contracted` and `no_policy` give `policyPenaltyMinor = 0`.
- `tier` = first of the tiers sorted by `minDaysBeforeDeparture` descending with `days ≥ min`, else the tier with `min = 0`.
- A fixed tier whose currency is not the booking's → `PricingError('cancellation_currency_mismatch')` → 409 (fails closed; cannot happen if the assignment check holds).
- `held = max(collectedMinor, 0)`; `penaltyMinor = min(policyPenaltyMinor, held)`; `waivedMinor = policyPenaltyMinor − penaltyMinor`; `refundableMinor = held − penaltyMinor`.
- `validatePolicy(tiers)` (used on activation): at least one tier; thresholds unique integers in `[0, 3650]`; one at 0; `percent` ⇔ `penaltyBps ∈ [0, 10 000]` and no amount/currency; fixed ⇔ `penaltyMinor ≥ 0` (≤ the 1.1 cap) and a currency; one currency among fixed tiers; at most 10 tiers.

## 6. Flows

**Quote** (`CancellationService.quote`): read-only transaction; reads the booking, its current snapshot's policy (through `pricing`), places and total from the snapshot, and the money facts from the port; returns the section 4 result, `currency`, `businessDate`, the blocking reason if any, `canCancelOnline` (customer only) and `quoteDigest` = SHA-256 of `bookingId | booking.version | snapshotVersion | businessDate | basis | tier | policyPenalty | penalty | refundable` (opaque, not an amount).

**Cancel** (`CancellationService.cancel(bookingRef, { actor, by, version?, reason?, quoteDigest? })`), one transaction, `PAYMENT_TX_OPTIONS`:

1. Lock the booking (`FOR UPDATE`). Lock order is plan 0.1, 6.3 "cancelar": Booking → PromoCode → pools → (Payment never locked here).
2. Customer: setting on, owner (route guard), state in `deposit_paid`/`confirmed`/`balance_paid`, policy present, `days ≥ 0`. Staff: step-up (existing `bookings.booking.cancel` permission).
3. Money facts from the port (`collectedMinor` from `bookingCash`, blockers of decision 8), read without Payment locks: every change of a payment locks this booking first.
4. Compute the quote; if `quoteDigest` was sent (always by customer and panel; optional for staff API callers) and differs → 409 `cancellation_quote_changed` (the day flipped, a payment arrived, the booking changed).
5. Insert the `Cancellation` (unique `bookingId`: a second click that got past the lock finds the booking `cancelled` and gets 409 `transition_not_allowed`; the unique index is the backstop, mapped to 409 `already_cancelled`).
6. `stateMachine.transition(tx, id, 'cancel', { actor, version, reason, cancellation: { id, penaltyMinor } })`. The table gains `cancel` from `deposit_paid`, `confirmed`, `balance_paid`; `MONEY_CELLS` and `cancellation_needs_payments` go. The hook context carries `cancellation`.
7. Payments' `cancel` hook (replacing today's refusal): with a schedule, bump its version, supersede every active item and, when `penaltyMinor > 0`, insert one active item `kind = penalty`, `sequence 1`, amount `penaltyMinor`, due `businessDate`; then `ledger.reallocate(…, 'cancellation:<cancellationId>:plan')` (P5): the excess moves to `customer_overpayments`. The live attempt job is queued as today. Without a `cancellation` in the context (no caller should do this) the hook keeps refusing a booking with money collected (409), so no path skips the record.
8. The state machine releases claims and code once and promotes the waitlist (6.5), audits, publishes. After it, `bookings.cancellation.recorded` (ids only) and, if `refundableMinor > 0`, a task (`sourceRef bookings:cancellation_refund_due:<bookingId>`): "Refund due on MT-…: A$… (cancellation)".
9. Coverage C after the hook: `cancelled` with money and collected 0 → `refunded` (only reachable with penalty 0 once refunds succeed), as 4.5 left it.

**Refund for a cancellation** (`AppRefundsService.create`, purpose `cancellation`): the request body is unchanged (no amount, no id). With Booking → all Payments locked: booking `cancelled` and a `Cancellation` exists, else 409 `cancellation_refund_rejected_until_cancellations_exist` (kept: "until one exists for this booking"); `capRemaining = refundableMinor − Σ amount of this booking's cancellation refunds in `requested`/`pending`/`succeeded`` (failed and reversed free the cap, P10); `capRemaining ≤ 0` → 409 `cancellation_refund_cap_reached`; amount = `min(refundable(p), capRemaining)`; the 4.5 checks (disputes, external/late pending, `nothing_to_refund`, `partial_refund_not_supported` compared with the new amount) stay; insert with `cancellationId` from the server. Money that arrives after the cancellation is an overpayment above the cap: it goes back as `overpayment_return`. The refundable view adds `cancellationRefundableMinor` per payment, computed by the API.

**Policies (panel)**: create/edit drafts with tiers (optimistic version), activate (step-up, validation in service and trigger), archive (step-up; 409 `policy_in_use` while assigned), duplicate an active policy into a new draft (to "edit" one), assign/unassign a package's policy (step-up, currency check). Every change audited.

## 9. Failure cases

| Case | Answer | Test |
|---|---|---|
