# Plan 7.fix-3: organiser exports, fixes from the independent review of 7.2

Risk: high (personal data leaves the system). Scope: `apps/api/src/modules/organiser-exports/` and its tests only. No migration, no new dependency, no change to other modules. Base: `docs/plans/7.2-organiser-exports.md` and `docs/done/7.2.md`.

## 1. Findings and fixes

1. **Audit cannot say who was in a file (medium).** Today the entry holds format, distance and row count. After a breach, or when a runner asks "who got my data?", nobody can tell. Fix: the `after` of `exports.runnerData.generated` also holds `places`, the list of `{ reference, slot }` exported, in file order, classified `nopii`. Why that is not personal data under the repo's conventions: `Booking.reference` is annotated `@nopii` ("human reference MT-XXXXXX, random") and slots are small integers; both are already in the dry-run answer and in the 422 issue list, which are designed to carry no personal value. The pair is a pseudonymous key: it identifies a person only by joining to `traveller`, which erasure wipes, so the audit row keeps working after an erasure without keeping a name. No name, date, contact, header or cell value goes into the entry, and still no `audit_pii_values` row. Size: at most `MAX_EXPORT_RUNNERS` (5000) pairs, about 100 KB of JSON in the worst case, once per file: acceptable for a rare, staff-only action.
2. **Demo data is exported (low).** The reader filters on status and participation but not on demo flags. Fix: the `bookingTraveller` query adds `booking.isDemo = false`, `booking.customer.isDemo = false` and `booking.edition.race.isDemo = false` (the same three flags 7.fix-1 used in `reports/engine.ts`). Demo places are not read at all, so they are not counted as erased either. A demo race (always a draft) still resolves as an edition, so its answer is `no_runners`, not 404: assumption, the conservative choice that changes no existing answer.
3. **Formula injection when the organiser's spreadsheet splits on the other separator (low).** A comma-separated file opened with `;` (or the reverse) splits a cell, and a fragment after the split can start with `=`. Fix in `render.ts`, local to this module (the platform `guardCell` is shared with the table capabilities import and is not changed): a cell is quoted when it holds `"`, `,`, `;`, CR or LF, whatever the format's delimiter; and the formula guard runs on every fragment of the cell split on `,` and `;`: a fragment whose text, after its leading whitespace, starts with `'*` and then `=`, `+`, `-`, `@`, tab or CR gets a `'` in front of that character. The first fragment is the cell start, so the old behaviour is a special case. The existing assertion that `=A1,B1` stays unquoted in the semicolon format describes the bug; it becomes the stricter `"'=A1,B1"`.
4. **Missing tests (low).** (a) The 61st dry-run check in an hour by one staff user is 429 with `Retry-After`, and another user is not affected. (b) End to end through the API: a format restricted to race A is listed for an edition of race A and works there; on an edition of race B it is not listed and the check and the file answer 404 `format_not_found` with the same body as an unknown format. No shipped format is restricted, so a separate test file adds one with `vi.mock` of `formats.ts` (built with the real `defineFormat`), without touching production code.
5. **Documentation only.** See section 4.

## 2. Tests first

- `exports.test.ts`: audit entry has `places` equal to the exported `{ reference, slot }` list (excluded and erased places not in it), the whole row's JSON holds no given name, family name, date of birth or emergency contact, and `piiValues` is empty; a demo booking on a real race, a booking of a demo customer, and a booking on a demo race are not in the file, not in the check counts and not in `erased`; check limit 60 then 429.
- `formats.test.ts`: a distance name `Marathon;=HYPERLINK("http://evil.test","x")` in the basic (comma) format and in the international (semicolon) format is quoted and its `=` fragment is guarded; a comma variant too; leading spaces before the formula character; a value that only contains `-` in the middle of a fragment (`10 km - fun run`) is untouched.
- `restricted-format.test.ts`: section 1, item 4(b).
- Each fix is broken by hand once to see its test fail.

## 3. Not in this task

Changing the shared `guardCell` / `toCsv` of the platform (other modules); moving the rate limits out of memory; a panel screen; any migration.

## 4. Corrections to the 7.2 plan (as built)

- The per-IP file limit is **100 files per hour**, not 10 as the 7.2 plan said: several staff can share one office address. The per-user limit is 10 files per hour; checks are 60 per hour per user.
- `appliesTo.years` was dropped: a format is restricted by race slug only (`appliesTo.raceSlugs`).
- The limits are **in memory**: a restart forgets them, and with N API instances each holds its own counts, so the real ceiling is N times the figure. Accepted for now (same as the customer document guard); a shared store is a follow-up if more than one instance is run.
