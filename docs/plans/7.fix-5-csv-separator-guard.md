# Plan 7.fix-5: CSV formula guard for the other separator (platform helpers)

Risk: high (personal data exports: table exports, rooming and transfer lists). Scope: `apps/api/src/platform/common/csv.ts` and tests. No migration, no new dependency, no change to `organiser-exports` (7.fix-3) or `reports` (7.fix-4). Model: the fragment guard of PR #67 (`organiser-exports/render.ts`), implemented here in the platform independently.

## 1. Problem

`toCsv` writes comma files and quotes a cell only when it holds `"`, `,`, CR or LF; `guardCell` only looks at the start of the cell. A spreadsheet that splits on `;` (European Excel, LibreOffice with a `;` locale) turns `Marathon;=HYPERLINK("http://evil.test","x")` into a cell starting with `=`. The same applies the other way to a comma fragment of a cell when the file is read with a different separator. Customer-typed or staff-typed text reaches these files: table exports (`platform/common/csv.service.ts`), catalogue exports (`modules/catalogue/csv.service.ts`), rooming, transfer and itinerary lists (`modules/tripops/lists.ts`, hotel, room, transfer and traveller names).

## 2. Design

1. **Quoting.** `quote` in `csv.ts` also quotes a cell (and a header) holding `;`. So a `;` reader keeps such a cell whole and a comma reader is unchanged.
2. **Fragment guard.** `guardCell(text)` splits on `,` and `;` (keeping the separators), and for each fragment skips its leading whitespace except tab and CR (those are formula characters themselves) and applies the existing rule: text starting with `'*` and then `=`, `+`, `-`, `@`, tab or CR gets one `'` in front. The first fragment is the start of the cell, so every existing single-cell result is unchanged, except a cell whose formula character follows leading spaces (`"  =1"` now becomes `"  '=1"`, which is stricter: some readers trim).
3. **Reverse.** `unguardCell` applies the same split and removes one `'` from each fragment that starts (after the same whitespace) with `'+` and a formula character. Guarding only inserts `'`, never a separator or whitespace, so the fragment boundaries are the same on both sides and `unguardCell(guardCell(x)) === x` for every `x` (the existing argument per cell holds per fragment). The importers (`csv.service.ts` in platform and catalogue) already call `unguardCell` on each cell, so imports of new exports read back the original text; multiselect custom fields (`"a; -b"`) round-trip.
4. **Compatibility with 7.fix-3.** Its `guardFragments` calls `guardCell` on a fragment without separators and without leading whitespace; on such input the new `guardCell` is the old one, so the file is identical whichever PR lands first. On `main` today, `organiser-exports/render.ts` calls `guardCell` on the whole cell: it gains the fragment guard (stricter, no file change in that module).

## 3. Failure cases considered

- A text that already looks guarded after a separator (`a;'=b`): guarded to `a;''=b`, unguarded back to `a;'=b`.
- A file exported before this change that holds `a;'=b` reads back as `a;=b` on import. Accepted: it needs a quote typed by a person after a separator and before a formula character; noted in the done file.
- `-` in the middle of a fragment (`10 km - fun run`), `1=1`, `a-b`: untouched. Numbers, booleans and dates are not text and are not guarded (a negative number stays `-5`).
- Visible cost: a name like `Smith, -5 km` is exported as `"Smith, '-5 km"`. Accepted, as in 7.fix-3.

## 4. Tests first

- `test/platform/csv-separators.test.ts` (new, pure): table-driven cells (formula after `;`, after `,`, after `, ` and `;  `, tab and CR after a separator, quotes, CR/LF, plain text, `-` mid-fragment, already-guarded text); for each: the written cell, a read of the whole `toCsv` file with a quote-aware reader using `,` and one using `;`, where no resulting field (trimmed) starts with a formula character, and the round trip `parseCsv` + `unguardCell` gives back the original row. Plus quoting of `;` in headers.
- `tripops.test.ts`: a hotel, room and transfer name holding `;=HYPERLINK(...)` comes out quoted and guarded in the rooming and transfer CSV (pure, through `roomingCsv` / `transfersCsv`).
- Existing tests that bless the old output are updated only if they do (none expected); `source-conventions` stays green.
- Each half of the fix (quoting of `;`, fragment guard, unguard) is broken by hand once to see a test fail.

## 5. Not in this task

`organiser-exports` and `reports` modules; a tab-separated reader; changing `parseCsv` to accept `;`.
