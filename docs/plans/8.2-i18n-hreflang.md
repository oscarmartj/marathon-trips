# 8.2 Full internationalisation with `hreflang`

Risk: medium. Web only; no API change, no migration, no money. Sources: `docs/phases/phase-8.md`, `docs/web.md` (SEO), `docs/done/8.1.md`, `docs/done/5.7.md`.

## Design

- **A language is a catalogue file plus one line.** `apps/web/messages/<tag>.json` and an entry in `lib/locales.ts` (registered list) and `lib/i18n.ts` (catalogue map; typed so a missing entry fails the build). The data model needs nothing: content already has a `locale` column and the public API takes `?locale=`; catalogue names are `Record<locale, string>`.
- **Enabled is separate from registered.** `ENABLED_LOCALES` (comma list, default `en-AU`) decides which registered languages the site serves. Production stays English-only until Oscar enables one. A language not enabled 404s and has no `hreflang`.
- **URLs.** Default language has no prefix (`/races`); others use the tag as prefix (`/es-ES/races`). The app tree moves from `app/(public)` to `app/[locale]`; the proxy rewrites unprefixed paths to `/en-AU/...` and redirects `/en-AU/...` back to the unprefixed form. Pages keep `revalidate = 60` (locale is a route param, so they stay incrementally generated).
- **Remembering the choice.** The language switcher links to the explicit prefixed URL; the proxy stores it in a cookie (`mt_locale`) and rewrites unprefixed paths to that locale for return visits, so the many in-page `/races`-style links keep the language. Crawlers send no cookie, so every address stays one language. Header, footer, banner and language-switcher links are prefixed explicitly.
- **Which locale `t()` uses.** `t(key, params, locale?)`: explicit locale wins; otherwise the request locale set by the layout and each page (`setRequestLocale`, React `cache`, server only); otherwise the default. A key missing from a non-default catalogue falls back to en-AU (a partial translation never breaks a page); a key missing from en-AU still throws. Test: every locale's keys are a subset of en-AU's, with identical `{placeholders}`.
- **Content.** `getPage`, `getGuide`, `listFaqs`, `listBanners`, `getMenu` read the request locale. No cross-language fallback for content (8.1 decision stands): a language with no published page 404s on `/pages/<slug>`, shows the built-in (translated) wording on about/contact/legal, and has no `hreflang` pointing to it for that page. Menus with nothing published fall back to the built-in translated links. Legal pages keep the "pending legal review" notice in every language.
- **`hreflang`.** `pageMetadata({ locale, path, locales? })` emits one alternate per enabled locale (or per locale the content exists in) plus `x-default` (default language), canonical = own-language URL, `og:locale` from the tag. Sitemap lists each language of each page with `alternates.languages`.
- **`<html lang>`** comes from the locale. No root layout: `[locale]/layout.tsx` and `admin/layout.tsx` are separate roots.
- **Out of this task (documented).** Client components (checkout, builder, forms, account) still read the default catalogue; they are token- or session-bound, `noindex`, and need a React context provider across ~70 files. The staff panel stays English. Both listed in `docs/done/8.2.md`.

## Failure cases / tests first
Disabled or unknown locale (404, no prefix redirect loop); `/en-AU/x` redirects to `/x`; admin, api and files untouched by the proxy; cookie with a disabled locale ignored; missing key falls back; missing placeholder in a translation fails the parity test; hreflang never lists a locale with no content or not enabled; `x-default` always default; sitemap alternates.

## Not doing
Machine translation of the whole catalogue (a small `es-ES` catalogue covers the shared chrome and home, off by default); automatic `Accept-Language` redirects (bad for crawling and caching); translated URL slugs; right-to-left layout; money, prices or currency formatting changes.

## Assumptions
No new dependency. The tag is used as the URL prefix. Language names in the switcher are written in their own language and kept in `lib/locales.ts`.
