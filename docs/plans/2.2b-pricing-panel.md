# 2.2b Pricing panel: price versions, rules and promo codes

Risk: medium. Sonnet. No plan reviewer (coordinator's call). Depends on 2.1 and 2.2 (merged). No money flows are touched.

## 1. Scope
Panel screens over the existing pricing admin API. No API change is planned; if one turns up it is minimal, declared in the PR and tested.

| Screen | Route | Does |
|---|---|---|
| Price versions of a package | `/admin/packages/[id]/prices` | list (draft, in force, scheduled, past, discarded), create (optionally copy the one in force), schedule/withdraw |
| One version | `/admin/packages/[id]/prices/[versionId]` | rate editor (rooms by occupancy, participation, extras, extra nights), completeness, quote preview with the draft, publish now or schedule (step-up), discard |
| Rules and promo codes | `/admin/pricing` (nav: Pricing rules) | list with filters, create, partial edit, enable/disable, validity, limits, redemption count, archive |

Package detail gets a link to the prices; the package list is unchanged.

## 2. Money in the browser
The web never adds, multiplies or divides money. A pure module `lib/pricing-panel.ts` does only text work:
- `parseMoney('1,234.5')` gives `'123450'` (string of cents) or a reason (`invalid`, `decimals`, `too_large`); no `Number`, no float. The line limit is compared with `BigInt` against `MAX_LINE_MINOR` (comparison only).
- `formatMinor('123450', 'AUD')` gives `A$1,234.50` by cutting the digit string.
- `parsePercent` to basis points by string cuts (up to 1 000 % for surcharges).
- Everything the API returns (rates, breakdown, totals, deposit) is displayed as returned. Tests: table-driven, including `0.1`, `.5`, `5.`, `1e3`, `-1`, `12.345`, grouping, the limit, and a source check that the module has no `parseFloat`, `Number(` on money, `toFixed`, `*` or `/`.

## 3. Rate editor
State is a map of text cells (one per room and occupancy, per participation type and distance, per extra). `cellsToBody` builds the `PUT .../rates` body from the cells and the package shape: an empty cell is "no rate"; a room price without an extra-night price sends `0` (the API reports `extra_night` as missing when the package offers extra nights). Cells for targets the package no longer has are dropped, and the screen says how many. Saving sends the version number (optimistic lock); the answer replaces the screen state. Publish is disabled while there are unsaved edits or missing rates.

## 4. Publish, schedule, withdraw
Publish sends `{version, replacesVersionId: lastId, validFrom?}` through `useStepUp` (existing flow). `validFrom` comes from a `datetime-local` converted with a pure, tested function (explicit offset). 409s have their own messages: `current_version_changed`, `later_version_scheduled`, `version_conflict`, `price_version_incomplete`, `price_version_starts_too_soon`; 422 shows the API's fixed message and the list of fields.

## 5. Rules and codes
One form for both (a promo code is a rule plus code, limits and no direction/kind). PATCH carries only changed fields plus `version`; `conditions` go whole when any changed (the API replaces them). Enable/disable is a PATCH of `enabled`. Archive asks for step-up like every change. `redeemedCount` is shown; `max_below_redeemed` has its own message.

## 6. Failure cases handled
Stale version (409 `version_conflict`: reload prompt), step-up cancelled (no change, message), 403 (no permission: message), network failure, invalid money text (field error, nothing sent), empty draft publish, quote errors (`rate_missing`, `occupancy_out_of_range`... shown with the API message).

## 7. Tests (written with the code)
- `lib/pricing-panel.test.ts`: money, percent, datetime, cells/body round trip, quote request builder, PATCH diff, source purity.
- Copy test already forbids hard-coded text; keys in `messages/en-AU.json` under `admin.pricing`.
- Component tests for the error mapping and the editor body (jsdom, if the web package has the setup; else logic-only).
- e2e `pricing-panel.spec.ts`: demo package, create version, fill rates, save, preview, publish by the panel, see it in force, create a code. CI runs it.

## 8. Not doing
Bulk rate import, price history comparison, rule simulation beyond the preview, per-currency formatting beyond AUD, any change to the engine, payments, permissions (existing ones suffice; none added).

## 9. Assumptions (no Oscar)
Staff work in their browser's time zone for `validFrom` (shown with the zone name). Scope pickers list the latest 50 packages (and the one named in the URL). `stackable` stays false by default.
