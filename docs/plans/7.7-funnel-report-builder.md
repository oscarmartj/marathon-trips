# Plan 7.7: funnel per race and report builder with scheduled sending

Risk medium. Reference: `docs/phases/phase-7.md` (row 7.7), `docs/modules.md` (module 14), `docs/architecture.md` ("Plataforma": report builder), `docs/done/2.5.md`, `3.5.md`, `7.3.md`, `7.4.md`, `.claude/rules/web.md`. Money is parked: no amount, price, payment row or ledger is read or written. "Paid" is counted from the booking status only.

## 1. What is built

**Module** `apps/api/src/modules/reports/` (flag `module.reports`, one line in `modules.registry.ts`), schema `reports.prisma`, migration `0024_reports`.

| Table | Purpose / guards |
|---|---|
| `race_daily_stats` (`raceId`, `day` DATE in Brisbane, `views`, `builderUses`; PK `(raceId, day)`) | Anonymous daily counters. No IP, cookie, user agent or session is stored. API role: SELECT/INSERT/UPDATE, no DELETE/TRUNCATE. CHECK counts >= 0 |
| `saved_reports` (name, `entity`, `definition` JSON, `schedule` JSON?, `recipientUserIds` uuid[], `ownerUserId` FK `users(id, kind)` staff, `scheduleStartedAt`, `version`, soft delete) | Staff text, `@pii`. Soft delete only (no DELETE/TRUNCATE for the API role) |
| `report_runs` (`reportId`, `scheduledFor`, `status` sent/skipped, `reasonCode?`, `recipients`, `createdAt`) | Unique `(reportId, scheduledFor)`: one run per scheduled time, also across API instances. Ids and codes only |

**Visits.** `POST /analytics/race-events` (public, 60 per minute and address, and one count per address, race and kind every 30 minutes, kept in memory only) with `{ raceSlug, kind: view|builder }`. A published, non-deleted race gets `INSERT .. ON CONFLICT (raceId, day) DO UPDATE SET views = views + 1`; anything else gets the same 204 (nothing to learn). Web: a tiny client component `RaceBeacon` on the race page (`view`) and the package page that hosts the builder (`builder`), sending one `fetch(..., { keepalive })`; nothing is read back. Counts are indicative (bots and reloads are not filtered); this is stated in the panel.

**Report catalogue** (closed, in `packages/shared/src/schemas/reports.ts`). Two entities, no personal data in either (no names, emails, references):
- `funnel`: columns `views`, `builder_uses`, `requests`, `approved`, `paid`, `request_rate_pct` (requests per 100 views), `paid_rate_pct` (paid per 100 requests); groups `race`, `month`, `none`. Needs `reports.funnel.read`.
- `bookings`: columns `bookings`, `approved`, `declined`, `expired`, `cancelled`, `paid`; groups `race`, `edition`, `package`, `channel`, `month`. Needs `bookings.booking.read`.
Definition: `{ entity, columns (1..10, from the entity), groupBy, raceIds? (<=50), range: { kind: 'last_days', days 1..366 } | { kind: 'dates', from, to } }`. Every figure is a cohort: bookings are counted by the Brisbane day they were requested, and approved, declined, expired, cancelled and paid say how many of those reached that point (paid = current status in deposit_paid, confirmed, balance_paid, completed), so rates stay <= 100. Demo races and demo bookings are left out. Days are Brisbane days. Rows capped at 500 (`truncated`). Rates use integer arithmetic, one decimal.

**Engine** `ReportEngine.run(tx, definition, now)`: whitelisted SQL fragments (constants, never user text) with bound parameters; the one place counts are computed. The web only displays.

**Scheduled sending.** `schedule = { frequency: weekly|monthly, weekday 1..7, dayOfMonth 1..28, time HH:MM (5-minute steps) }` in Brisbane time (no daylight saving). Queue `reports.tick` (every 5 minutes, migration + `queues.ts`): for each report with a schedule, the latest occurrence <= now that is after `scheduleStartedAt` and at most 6 h old gets a `report_runs` row (`ON CONFLICT DO NOTHING`; missed older occurrences are not caught up). The first inserter checks the owner (active staff, holds `reports.report.read` and the entity permission) and each recipient (same checks) and queues one email per eligible recipient (`dedupeKey report:<runId>:<userId>`), counting the others as skipped; no eligible owner = run `skipped/owner_unavailable`, a system task once. The email template `reports.scheduled` v1 renders at send time from the run id: it re-checks the recipient (still active staff with the permission, else `mail_not_sendable`), re-runs the definition with the run's `scheduledFor` as "now" and prints a plain-text table (<= 100 rows). Recipients can only be active staff users, never free addresses, and mail goes through the usual mail guard (development mailbox).

**Permissions** (none API-key scopable: they expose business metrics and cause emails): `reports.funnel.read`, `reports.report.read`, `reports.report.manage`. Running or previewing a saved report also needs the entity's permission. Whoever saves a report becomes its owner.

**Routes** `/admin/reports` (`@RequiresModule('reports')`): `GET /funnel?days|from&to` , `GET /catalogue` (entities, columns, groups, races, staff recipients), `GET /`, `POST /`, `GET /:id`, `PATCH /:id` (`version`), `DELETE /:id` (`version`), `POST /preview` (a definition, no save), `POST /:id/run`. Audited (`reports.report.created|updated|deleted`).

**Panel.** `/admin/reports`: funnel table (7/30/90 days), saved reports list, builder form (entity, columns, group, range, schedule, recipients), preview table. Nav link, copy in `en-AU.json`, Playwright `apps/web/e2e/reports.spec.ts` (E2E_STAFF_19).

## 2. Assumptions (conservative, reversible)
1. "Payments per race" = bookings that reached a paid status; no amounts (money parked). Amounts can be added as columns later.
2. Visits are an anonymous counter, no consent needed because nothing identifies a person; not de-duplicated.
3. Recipients are staff only; reports hold no personal data, so no erasure hook (entities registered with no customer link).
4. Report text email is built in (staff-only, English); not a 5.4 template.
5. Schedule weekly/monthly only (no daily, no every-minute).

## 3. Failure cases and tests (written first)
`test/modules/reports/pure.test.ts`: definition schema (unknown column/group for the entity, duplicates, range limits, race cap), schedule occurrence (weekly, monthly day 28, 6 h window, before `scheduleStartedAt`), rate arithmetic. `reports.test.ts` (PostgreSQL): beacon counts and ignores unknown/draft/deleted races; funnel and bookings figures on seeded data (cohort, range edges at Brisbane midnight, month grouping, race filter); permissions (403 without entity permission, 404 flag off); saved report CRUD with versions and audit; tick creates one run under concurrency, skips an inactive owner, drops a recipient who lost the permission, enqueues one email per recipient; render refuses a recipient who lost access; no personal data in the result. Web: unit test of the helpers, copy test, Playwright spec.

## 4. Not doing
Amounts or money columns, ledger, custom entity columns (7.5 fields), CSV attachments, charts, free-form recipients, de-duplicating visits, other entities (customers, payments).
